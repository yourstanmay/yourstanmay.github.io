Core Java

Focus on what you actually use in Hybris — Collections, OOP, Concurrency, Exception handling.

Q1 What collections have you used? Explain internal implementation of HashMap. ▾
Collections Used
HashMapArrayListLinkedList HashSetLinkedHashMapList
HashMap Internal — How it works
1Internally uses an array of Node<> (buckets). Default size = 16, load factor = 0.75.
2On put(key, value): key's hashCode() is calculated → index = hash % capacity.
3If bucket is empty → store Node. If collision → linked list chaining at same index.
4Java 8+: if chain length > 8 → converts to Red-Black Tree for O(log n) lookup.
5When size > 0.75 × capacity → rehashing: new array of double size, all entries re-mapped.
💡 Key point: HashMap is NOT thread-safe. Use ConcurrentHashMap for thread safety.
ArrayList vs LinkedList
ArrayList
Fast random access O(1). Slow insert/delete in middle O(n). Backed by array.
LinkedList
Slow random access O(n). Fast insert/delete at head/tail O(1). Backed by doubly-linked nodes.

Q3 Explain inheritance vs polymorphism ▾
Inheritance
Child class acquires properties of parent. Promotes code reuse. is-a relationship. Example: ProductModel extends ItemModel.
Polymorphism
Same method name, different behavior. Runtime (method overriding) or Compile-time (method overloading). Example: different CartStrategies having the same split() method.
💡 In Hybris: AbstractOrderModel → CartModel / OrderModel is classic inheritance. Different cart splitting strategies implementing the same interface is polymorphism.

Q6 Explain POST vs PUT request methods ▾
POST
Creates a new resource. Not idempotent — calling twice creates two records. Example: Create new cart, place order.
PUT
Updates/replaces existing resource fully. Idempotent — calling twice = same result. Example: Update cart entry quantity.
💡 PATCH = partial update. In OCC APIs, most cart operations use POST/PUT.

SQL & FlexibleSearch

Hybris uses FlexibleSearch (HSQL-like) instead of raw SQL.

Q1 SQL: Count employees per department (emp + dept tables) ▾
Answer
SELECT d.dept_name, COUNT(e.emp_id) AS employee_count FROM dept d JOIN emp e ON d.dept_id = e.dept_id GROUP BY d.dept_name ORDER BY employee_count DESC;
💡 Use LEFT JOIN if you want departments with zero employees included.
Q2 Write a FlexSearch to fetch all products associated with one category ▾
SELECT {p:pk} FROM {Product AS p JOIN CategoryProductRelation AS cpr ON {cpr:target} = {p:pk} JOIN Category AS c ON {cpr:source} = {c:pk}} WHERE {c:code} = 'electronics'
💡 In FlexSearch — use curly braces {} for type/attribute names. Relations use source/target instead of FK column names.

Data Modelling

items.xml is the heart of Hybris. Know it cold.

Q1 Explain data modelling in SAP Hybris — items.xml structure and element sequence ▾
"Data modelling in Hybris is done via items.xml. This file defines types (tables), attributes (columns), relations, and enums that get auto-generated into Java model classes and database tables."
Required element sequence inside items.xml:
1<atomictypes> — primitive type wrappers
2<collectiontypes> — list/set types
3<maptypes> — key-value map types
4<enumtypes> — enumerated values
5<relations> — type relationships
6<itemtypes> — actual type/model definitions
💡 Sequence matters! Hybris processes them in this order. Defining an itemtype before its enum causes build errors.
Where deployment tag is used:
"Deployment tag is used inside <itemtype> to map it to a specific database table. Without deployment, the type shares its parent's table. Add deployment when you expect many records or need independent table management."
<itemtype code="MyOrder" extends="AbstractOrder"> <deployment table="MyOrders" typecode="11234"/> <attributes> <attribute qualifier="giftWrapping" type="java.lang.Boolean"> <persistence type="property"/> </attribute> </attributes> </itemtype>
Q2 Relation vs Collection — differences, when to use, performance, how stored? ▾
Relation (recommended)
Stored in separate join table. Supports one-to-many, many-to-many. Can be queried with FlexSearch. Better for performance and large datasets. Example: Category ↔ Product.
Collection
Stored as serialized data in the parent type column. Can't be queried via FlexSearch. Fine for small, simple lists. Harder to maintain.
Schema for one-to-many Relation:
-- Relation creates a separate join table: -- Table: CategoryProductRelation -- Columns: PK, SourcePK (Category), TargetPK (Product), RSequenceNumber -- items.xml definition: <relation code="Category2ProductRelation" localized="false"> <sourceElement type="Category" qualifier="categories" cardinality="many"/> <targetElement type="Product" qualifier="products" cardinality="many"/> </relation>
💡 Always use Relation for one-to-many or many-to-many. Use Collection only for simple, non-queryable small lists.
Q3 Types of relations in SAP Commerce Hybris ▾
One-to-OneOne-to-ManyMany-to-Many
1One-to-One: Single source → single target (e.g., Order → PaymentInfo)
2One-to-Many: Source has many targets (e.g., Order → OrderEntries). Stored as FK on target side.
3Many-to-Many: Both sides have multiple (e.g., Category ↔ Product). Creates join table.

Q6 What are interceptors in SAP Hybris? Types? ▾
"Interceptors are hooks that execute during model lifecycle events — before or after save/remove/load."
1ValidateInterceptor — runs before save. Use for validation. Throw InterceptorException to block save.
2PrepareInterceptor — runs before save. Use for auto-populating fields (e.g., set creationDate).
3RemoveInterceptor — runs before delete. Use to prevent deletion or cleanup related data.
4LoadInterceptor — runs after model is loaded from DB. Rarely used.
5InitDefaultsInterceptor — runs when new model is created. Sets default values.
Interceptor vs Filter
Interceptor
SAP Hybris concept. Works at model persistence layer. Hooks into save/load/remove lifecycle.
Filter
Standard Java/Spring concept. Works at HTTP request layer. Intercepts incoming requests before they reach controllers.

Catalog & Categories

Q1 What is the difference between Catalog and Category? ▾
Catalog
Top-level container for all product data. Has versions (Staged / Online). Example: "Electronics Catalog". Contains CatalogVersions.
Category
Organizational grouping within a catalog. Hierarchical. Example: Electronics → Phones → Smartphones. Products are assigned to categories.

Q2 What are DTOs? How do you display required attributes from model to API response? ▾
"DTOs (Data Transfer Objects) are simple Java objects used to carry data between layers — particularly from the service layer to the API response. They avoid exposing model internals directly.

In Hybris, DTOs are defined as beans in *-beans.xml and get auto-generated. You control what gets exposed in the API response using Populators."

2Create a Populator class that maps Model → DTO: populate(ProductModel, ProductData)
3Register populator in a Converter bean in spring XML
4Inject converter in the controller/facade and use it to convert model → DTO → JSON response

Cart, Order & Payment

Core commerce flows. Expect at least 3-4 questions from this area.

Q1 Explain Cart and Checkout flow — how product gets added, entries created, cart calculation ▾
1User adds product → CartService.addToCart() is called → creates AbstractOrderEntry with product, qty, unit
2Cart Calculation runs: sums entry prices, applies promotions, computes taxes, sets total
3On checkout: address, delivery mode, payment info set → PlaceOrderAction executes
4Cart is converted to an Order via orderService.placeOrder(cart)
5Business Process starts → handles payment, warehouse, fulfillment
Calculation vs Recalculation
Calculation
Full fresh calculation of cart. Runs all promotions from scratch. Called after adding to cart.
Recalculation
Recalculates existing values. Promotions do NOT re-run. Use for price updates without re-evaluating promotions.
💡 Promotion engine triggers during Calculation, not Recalculation.
Q2 What are Cart Splitting Strategies? ▾
"Cart Splitting Strategies split a cart into multiple consignments/sub-carts based on business rules during order placement."
OrderSplittingServiceAbstractSplittingStrategy
1By Warehouse: Entries fulfilled from different warehouses → separate consignments
2By DeliveryMode: Different delivery modes → split delivery
3By Parameters: Custom splitting — e.g., digital vs physical items, B2B approval levels
4Custom strategy: extend AbstractSplittingStrategy → override getGroupingObject()
Q3 Anonymous cart — what happens when user logs in or proceeds to checkout? ▾
1Product added by anonymous user → stored in anonymous cart (guid-based, not linked to user)
2User logs in → Hybris checks for existing user cart
3CartRestoreStrategy merges anonymous cart entries into user cart (or replaces)
4Cart is now linked to user session — checkout can proceed
💡 This is the "guest cart merge" behavior. Hybris handles it via CommerceCartService.restoreSavedCart()
Q4 How is inventory managed when product is added to cart and order is placed? ▾
1Add to cart → availability checked via CommerceStockService. No reservation yet at cart stage.
2Order placed → StockLevelDecreaseAction in business process decrements stock
3If stock runs out between cart & order → handled by availability check at checkout
4Consignment created → warehouse system handles physical dispatch and updates availability
Q5 Explain payment flow and payment transaction process. What is 3D Secure? ▾
1User enters payment → OCC API calls CommerceCheckoutService.authorizePayment()
2Payment gateway called (e.g., Stripe, Adyen) → returns AUTHORIZATION response
3PaymentTransaction + PaymentTransactionEntry created in Hybris with AUTHORIZATION status
4After order confirmation → CAPTURE step (deduct actual money from card)
5If payment fails → order goes to PAYMENT_NOT_AUTHORIZED step in business process
3D Secure
"3D Secure (3DS) is an extra authentication layer for card payments. After entering card details, the user is redirected to their bank's page to verify via OTP or biometrics. In Hybris: after auth call, if gateway returns REDIRECT_SHOPPER, we redirect user to 3DS URL. After verification, gateway calls back our webhook with success/failure → we capture or fail the payment."
💡 Capture timing: We captured payment only AFTER order was confirmed and warehouse allocation was done — to avoid capturing for an order we can't fulfil.
Q6 Explain Business Process when user places an order ▾
1placeOrder() → Order created → Business Process started (order-process.xml)
2Send order confirmation email action
3Fraud check action
4Payment authorization / capture action
5Source order / warehouse allocation
6Ship goods / consignment process
7Order complete
Handling 3rd party timeout scenario:
"If the business process is waiting for a 3rd party response (e.g., warehouse confirmation) and no response comes in 4 hours — implement a Wait node with a timeout in the process definition. After timeout, a TimerAction triggers and transitions the process to a FAIL state with appropriate order status update."
<!-- In order-process.xml --> <wait id="waitForWarehouse"> <event>WarehouseResponseEvent</event> <timeout delay="PT4H"> <!-- ISO 8601: 4 hours --> <onTimeout><transition name="TIMEOUT"/></onTimeout> </timeout> </wait>

Solr & Search

Q1 What do you know about Solr? How is it used in Hybris? ▾
"Solr is a search engine used by Hybris for product search and faceted navigation. Hybris has a Solr integration layer (solrfacetsearch extension) that manages indexing and search."
1Products indexed via IndexerCronJob → sends product data to Solr
2Each indexed field has a Value Provider that extracts data from the model
3Search query → Hybris builds Solr query → results back → rendered to storefront
4Facets (filters), sorting, boosting configured in Backoffice
Q2 Value Provider vs Value Resolver in Solr ▾
Value Provider (older API)
Implements FieldValueProvider. Used in older Hybris versions. Returns field values for a product during indexing. One method: getFieldValues().
Value Resolver (newer API)
Implements ValueResolver. Newer, cleaner API. Supports batching, better performance. Use resolve() method. Preferred for new implementations.
Q3 What is Two-Phase Indexing? Why is it used? ▾
"Two-Phase Indexing is a Solr indexing strategy used to avoid search downtime during full re-indexing."
1Phase 1: Index all products into a NEW/inactive Solr collection (users still hit old collection)
2Phase 2: Once indexing complete → switch alias to new collection atomically
3Users now search the fully-indexed new collection with zero downtime
💡 Without two-phase: users see partial results during indexing. With it: atomic switch guarantees consistency.

Q4 How OCC APIs are secured? Authentication + OAuth configuration? ▾
"OCC APIs use OAuth 2.0 for authentication."
Client Credentials
B2B machine-to-machine. No user context. Used for system integrations.
Password Grant
User authenticates with username + password. Returns access token. Used for logged-in storefront users.
# OAuth token request POST /authorizationserver/oauth/token grant_type=password&client_id=mobile_android&client_secret=secret &username=user@example.com&password=mypass
Two simultaneous API calls — same session?
"OCC APIs are stateless. Each request carries its own OAuth token. Two simultaneous calls with the same token share the same user context but each is processed independently by available threads. No shared session object — thread-safe by design."

Q2 Recent challenge faced in your project and how you overcame it ▾
"During Go-Live of the Nitori Japan project, we faced an issue where QR payment callbacks (PayPay) were intermittently not being received by our webhook — causing orders to be stuck in PAYMENT_PENDING state.

I debugged by checking the payment transaction logs and found that our webhook URL was behind a firewall that blocked certain IPs from PayPay's servers. I worked with the infra team to whitelist the IPs, added retry polling logic in the payment status check cronjob as a fallback, and added alerting for stuck orders. This reduced stuck orders from ~15/day to zero."

Q4 Draw architecture for integrating a 3rd party system to SAP Commerce ▾

Inbound (3rd Party → Hybris): 3rd party calls our exposed OCC/OData endpoint or drops file in hotfolder → Hybris processes and stores data.
